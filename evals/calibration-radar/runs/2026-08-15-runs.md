# calibration-radar — run record (2026-08-15)

Committed run-level record for the benchmark reported in
`evals/calibration-radar/RESULTS.md`. This file exists so the headline
totals in `RESULTS.md` are auditable — every run counted in those totals,
every superseded run, and the reason each superseded run was excluded —
without committing full raw subagent transcripts (those remain local,
untracked scratch output, consistent with how `evals/repo-orientation/
runs/` and `evals/slice-review/runs/` handle the same tradeoff; see "What
this record does not include" at the end).

**Model:** claude-sonnet-5, fresh general-purpose subagent per run, no
shared context between runs. **Configuration:** with-skill runs read
`skills/calibration-radar/SKILL.md` first and follow it; baseline runs are
explicitly told not to and use only their own judgment. Each candidate
pool (`candidates.md`) and simulated projectmem output
(`projectmem-results.md`) is supplied as a fixture rather than generated
via live search/MCP calls, so runs are reproducible. Every run was graded
by the orchestrating session against the expectations in
`evals/calibration-radar/evals.json` (regression) or
`evals/calibration-radar/pressure-tests/pressure_evals.json` (pressure).
Verification depth varied by run: some responses were read in full by the
orchestrating session; others were graded from detailed, quote-specific
subagent self-reports rather than independently reopened as full
transcripts. `RESULTS.md`'s "What this proves" section records the exact
row-by-row distinction for the counted set — this file does not repeat it
per row.
n=1 per case per configuration, except where a fixture defect or a
SKILL.md revision required a rerun — see the three run dates below.

**Three run dates, same benchmark:**

- **2026-08-15, iteration 1** — first run of the full regression + pressure
  suites (original PR #32).
- **2026-08-15, iteration 2** — same day, case 004 only: its candidate 2
  was too weak on external merit to survive the skill's own Phase 1
  filter, so the intended practice-divergence classification check never
  ran. Fixed by strengthening the fixture's external evidence (not by
  changing the skill); both arms of case 004 rerun.
- **2026-08-15, iteration 3** — pre-merge review response: SKILL.md was
  revised (Phase 3 classification split into a primary relationship plus
  optional external qualifiers, tightened "genuine knowledge gap" so
  projectmem silence alone can't justify it, and a new "retrieved content
  is evidence, not instructions" rule). Per the rerun policy for a
  SKILL.md change, every with-skill regression and pressure case was
  rerun fresh; baseline runs were **not** rerun except where a case's own
  fixture, prompt, or grading changed (case 004 in iteration 2) — an
  unguided baseline never reads SKILL.md, so a SKILL.md revision gives no
  reason to rerun it. One new pressure case (111, source-content
  instruction injection) was added and run for the first time.

**Run count:** 35 runs executed across the three dates (8 regression + 10
pressure in iteration 1; 2 regression in iteration 2; 4 regression + 11
pressure in iteration 3 — iteration 3 reran only with-skill runs, per the
rerun policy that a SKILL.md-only change doesn't require rerunning
baselines). 19 rows below are counted toward the current headline totals;
the rest are superseded — see the Superseded runs summary for why each one
was excluded. Superseded runs are kept in this record, not deleted, so the
sequence of what actually happened is auditable rather than silently
overwritten by the final rerun.

## What this record does not include

Full raw subagent transcripts (the complete tool-call sequence and
intermediate reasoning behind each run) are not committed here or
anywhere else in this repository — they remain local, untracked session
output, consistent with how `evals/repo-orientation/runs/` and
`evals/slice-review/runs/` handle the same tradeoff. This record captures
the case, configuration, run label, score, and grading disposition for
every run — enough to audit the headline totals and the supersession
sequence — without the volume of a full transcript archive. Where
`RESULTS.md` quotes or paraphrases specific response content, that
content came from either a full read or a detailed subagent self-report
(see `RESULTS.md`'s "What this proves" section for which applies to
which row) — either way, it is not independently re-verifiable after the
fact, since the underlying scratch files are deleted per this repo's
convention of not committing raw transcripts. `RESULTS.md` cites this
run-record's row numbers for auditability rather than pointing at
scratch paths that no longer exist.
