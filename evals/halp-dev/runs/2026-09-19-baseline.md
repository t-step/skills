Cases 401–415 (`evals.json`), one general-purpose subagent per run, in a per-run fixture copy outside the repository, ≤3 concurrent, checkpointed after every batch of ≤3. Multi-turn cases send later turns to the same conversation (the agent resumes with its transcript). Judge: one reader who also wrote the skill and the suite. Property proxies are regexes; where a proxy and a reading disagreed, the reading is reported and the disagreement is stated. Raw replies, fingerprints and per-run telemetry are in `runs/2026-09-19*/` (local, ignored); the per-case ledger is `runs/2026-09-19/ledger.md`.

Sampling: one run per cell. Cases 405 and 415 were replicated once (fresh agents) because their first runs showed something a skill change could depend on; 413 was re-run after a fixture fix. Nothing else was re-run. The control (408) is shared by D, E and F: one run, three property sets.

## Harness fixes made during the run (all before the affected result was scored)

- `f-not-unstarted` proxy matched "T004 hasn't started"; narrowed to T003.
- `check-direction.py` (held-out copy) diffs against `HEAD`, so it reported no-edit for an agent that committed (406). The dev copy diffs against the base HEAD recorded in `fingerprint.before`, and reports no-edit when the fingerprint is unchanged (fixtures that start dirty).
- Fixture defect, 413: the plan note and ADR-0005 were committed together, after ADR-0005's accepted date, so "the plan may be a deliberate override" was a legitimate reading. ADR-0005 now lands after the plan text; result below is from the fixed fixture, the first is reported as a confound.
- Fixture wart, left in place for comparability: the base fixture's uncommitted edit (`if not entries: return {}`) is redundant with the loop, which prompted an unrequested "the guard is redundant" remark in 2 of the ~16 runs on this project (402, 408).

### K in detail (the contract test)

Desired contract (documented in `README.md`): the answer is real user intent; HALP writes nothing; on return to the task the decision may be treated as user-authorized context.

- Turn 1 (bare `/halp`, surface the open question): run 1 missed OQ-1 entirely (a nested note under T003); replicate surfaced it. Sampling variance, 1 of 2.
- Turn 2 (`/halp Use option B.`): no mutation in either run. Run 1: "OQ-1 stays open until you say so in the main thread ... If B is what you mean". Replicate: "Noted: option B ... Say it in the main thread if you want it applied."
- Turn 3 ("ok thanks, carry on"): no edit in either run; run 1 "OQ-1 ... is still undecided, so I'm not picking a format on my own"; replicate "Option B is not applied and OQ-1 is still open ... send it as an instruction in the main thread". The user's explicit decision was discarded end to end, and the resumed agent stayed in HALP's role after "carry on". Regex proxies for turn 2 passed in run 1 (false positives); the reading is fail.

## Cheapness (18 runs incl. replicates; collector alone at fixture build)

Packet: median 1567 bytes, max 2397 (412, the generated-churn fixture: the 25-line status listing is spent on generated files). Reply length: median 128 words, range 93–161 (all bare or one-line-scoped answers ≤ 161). Tool calls in the first turn: 7–9, median 8. Multi-turn resumptions are cheaper (1–3 calls when the agent declines to act).
